# Dataset findings that affect agent design

Source: executed [notebook](../analysis/explore.ipynb). Contextual matches and rare patterns are not ground-truth verdicts.

| Finding and number | Section | What to do |
|---|---|---|
| Identity formats differ by log: UPN in sign-ins and email, bare username in VPN, proxy, DLP, SQL and AD, `DOMAIN\user` in EDR, IPs only in firewall. One account's UPN misses **281** rows. `laura.ferrer` also returns **80** rows of `laura.ferrer2`. Hostname search misses **220** firewall rows. Typed normally, a `DOMAIN\user` value finds **0** rows in the mock, **117** with the backslash doubled. | 3, 12 | Resolve aliases per log; match parsed fields exactly. Never join on display name: **2** accounts share the traced case's. |
| Links are incomplete: **15,683 references**, **0 missing**, yet the `laura.ferrer2` chain omits **40 mailbox-access events**. **1** alert links nothing, and **334** of **336** links to later events come from `UC-NET-001`. One proxy window has **18,721** rows; the default limit returns the oldest **200**. | 4, 10 | Expand by entity/session/message ID; split saturated windows and deduplicate. Use event time. Truncated or trimmed evidence can't support the −1. |
| Context exceeds budget: about **14,000** characters remain for data. Raw rows fit for **45.5%** of alerts, **53.7%** without **8** IPs shared by many identities. One identity alert has **5** rows for its user and **2,031** from one shared IP. Without those IPs RB-03 rises from **7.6%** to **99.5%**, but RB-01, RB-02, RB-04, RB-06, RB-09 and RB-10 stay at **32.4%** or less. | 5 | Don't search on shared IPs. Send rows most important first and repeats as counts. Token counts are estimates. |
| Untrusted approval claims: **12 alerts** cite absent `SEC-4471`; **3 TPV alerts** cite absent `SEC-2210` in service descriptions. | 8, 9 | Keep retrieved text untrusted. Validate calendar existence, scope and time in code; keep approval tools outside LLM authority. |
| Prompt injection: text addressed to analysts or automated systems appears in **45 email records** and **12 alerts**, in the same fields as hidden HTML. The zero-width and bidirectional character screen finds **0**. The word screen flags **1,960** records, most of them ordinary: **415** alert descriptions repeating detector wording, **1,349** EDR command lines and **224** customer corrections. Text aimed at Vela, the shopping assistant, is a different risk from text aimed at the SOC. | 9, 11 | Treat every retrieved field as quoted data, not only Vela prompts. Text can't approve, change policy, set severity or give a verdict: check those in code. Report suspicious text in `injection_flags` as a lead, not an attack label. Test with a fake model that obeys planted text; never put that text in prompts. The screen misses reworded, encoded, split and other-language instructions. |
| Severity: the matrix changes **3,497 alerts** under the decided order, **3,495** of them on an assumed service rating. **3,406** are blocked web alerts that return to rule severity after the −1, leaving **91**. `Media` and `Alta` give identical results. The example ticket drops `medium` to `informational`: **two levels**, exceeding policy's one. | 6 | Record criticality provenance, matrix base and one bounded adjustment. Provisional until checked per alert. |
| Calendar: **26** start/end values lack offsets. Raw scanner traffic starts at 23:05 UTC for three weeks, then 00:05 after the clock change. **19** scanner alerts fit; fixed-offset windows also contain them. | 7 | Use `Europe/Madrid`, retaining the timezone inference as an assumption. Window inclusion alone cannot prove authorisation. |
| Encoded PowerShell: **1,349** alerts run **1** command on **769** laptops. **18** look outside 08:00-10:00 by alert time, **0** by event time. The calendar names `svc_sccm`; all **1,349** are logged as `NT AUTHORITY\SYSTEM`. | 2, 8 | Compare windows with event time. Accept that account only with the same parent, command and window. Rarity does not prove malice. |
| HR and company rules (leads): a dated trip covers `ALR-20261011-011873`. An employee leaving has data-loss alerts before their last day: `ALR-20261014-011817`, `ALR-20261015-011818`. **7** `adm.*` rows are outside JUMP01 and the approved change. `ALR-20261013-011816` is a login by the MFA-exempt `svc_backup`. | 8 | A dated trip can authorise. Other HR events are context only, and an exemption doesn't authorise a login. |
| Incidents: one case is traced. **37** rare-rule or absent-claim alerts are in no chain or authorised context. | 10 | Group across days, and treat these as leads until traced. |
| ID numbers: **19** of 19 tables have **1** break in their numbering, which may reflect how the data was built. | 1 | Never use ID numbers as a signal in code, prompts, rules, test selection, labels or scores. |
| Sample gaps: **150 alerts** omit **20 of 41 observed rules**, with **0 critical alerts**, and hold **2** of **15** absent-claim alerts. **33** additions are listed in look-alike pairs. **4** alerts are held out, **1** of them already in the sample. | 11 | Label independently; split whole incident groups; don't tune on held-out alerts. Do not claim a clean holdout: this analysis has read them. |
| Mock gaps: exact OT-host isolation returns **403**; **2 aliases** return **200**. Token replay and single-approver server/TPV isolation also return **200**. | 12 | Authenticate human approval, enforce roles and canonical targets, reject OT actions, and use single-use approvals. Require a person for every containment action. |

Unverified: other incident leads, injection-screen recall, incomplete authorisation matches, the link between the build alert and the cloud case, whether the shared IPs are office connections, model quality, exact tokenisation, live-test performance and real-world effects.
